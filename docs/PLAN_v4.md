# Kaggriculture v4：cha22 程序骨架 × 可学习插入点 × TTT 对手模型 × 先离线 RL × 快慢分离

## 0. 一句话
- **不用 MoE**。cha22 作为"程序骨架"保留（单位动作、路线动作带），在它内部手写、手调的决策点上插入可学习模块。
- **插入点**：卖出时机与数量、肥料自用还是卖、原料采购、雇工数、路线选择、对手识别（§2）。每个插入点先量上限，只给有上限的点装学习器。
- **TTT** 在正式对局中每步用观测到的对手流量更新快权重，给各插入点提供对手预测（§3）。
- **训练**：先离线 RL（分叉数据上的 IQL/AWR），再在线关键步 GRPO；关键步就是插入点被调用的时刻（§4）。
- **规划器删除**；MoE 相关代码随插桩代码一起删除。

## 1. 证据：为什么这样设计

### 1.2 今天核对的规则（官方解释器 `kaggriculture.py`）
1. **两个玩家之间唯一的交互渠道是共享的市场库存**。HIRE 和 BUY_LAND 只作用于各自的农场；城镇商店的解锁是随机的外生过程。
2. **库存变化**：
   - 每卖出一件，该商品的库存 +1；成交价为 1 时库存不变。
   - 城镇消耗是无条件扣减的：每 4 步，每个已解锁的商店扣 1 件（单品商店扣 2 件）；每 24 步，城镇中心扣 1 件（不含肥料）。
3. **高价品的价格曲线极陡**。相对初始库存多出下面的件数，价格就跌到地板价 1：牛奶 76 件、草莓 63 件、羊毛 59 件、甜瓜 158 件。
   - 肥料没有任何消耗，价格每多一件降 0.2，只降不回。
   - 甜瓜只有城镇中心消耗，每天 1 件。

### 1.4 关键推导：市场可分解性
**定义**：对手的净流量 o 和城镇消耗 d 合起来，构成"外生库存路径"

  E_τ = I_0 + Σ_{σ<τ} (o_σ − d_σ)

**结论**：城镇消耗是无条件的，而我们每卖一件都会让库存永久 +1。所以某种商品我们累计卖出的第 m 件，如果在时刻 τ 卖出，价格恰好是 p(E_τ + m)。这里忽略两点：地板价，以及同一步内双方逐件交错成交；我方的买单记为负的卖出。由此得到四点：
1. **总收入** = Σ_m p(E_{τ(m)} + m)，只取决于两件事：一共卖多少件，以及每件卖在外生路径的哪个位置。
2. **自己分批慢慢卖本身没有价值**。这解释了为什么之前按需求分批卖出的专家没有效果，也解释了为什么只看 1 步的 front_run 没用。
3. **对手不随价格反应时，最优策略是**：每件货在它的可卖窗口 [产出时刻, 终局] 里，挑 E 最低的时刻卖出。约束有两条：
   - 仓容 100 件，日终溢出的部分丢弃，用拉格朗日乘子处理；
   - 终局还没卖掉的货价值为 0。
4. **城镇消耗是已知的，所以唯一的未知量就是对手未来的市场流量 o。这正是 TTT 应该在测试时学的东西。** 对手会随价格反应的那部分（博弈），交给 RL。

### 1.5 对手流量在正式比赛中可观测（`tools/opp_flow_check.py`）
- 官方规格：双方农场（作物、动物、资金、雇工位置、地块）、市场库存与价格、城镇商店都是公开的；只有仓库、携带物品、种子是私有的。
- 只用正式比赛中 agent 能拿到的信息（公开库存变化 − 城镇消耗 − 我方成交），反推对手每步每种商品的净流量：**99.87% 的（步, 商品）完全正确**，大部分商品误差 < 成交量的 1.2%。
- 所以 TTT 的标签在正式对局中每步都能拿到，更新就在比赛中进行。

### 1.6 cha22 的内部结构（插入学习的依据）
- **路线**：预先录好的 719 步完整动作带（来自 yhay81 Shop Router、Ahmed Berat Ozer V39 等公开高手），卖单也写在带子里。
- **路由器**：第 144 步按"前两个商店"查表选路线（作者离线学的决策树，只用前两个商店里 YARN_STORE 的个数），第 648 步切终局路线。
- **反应层 + 65 个补丁**：大量手写、手调常数的市场规则，例如 R36 预留（把计划卖单最多提前 40 步）、RACE（对手上一步卖了而我们还持有就跟进）、RACEPX/RACEGATE（过剩闸门）、OVERFLOW（第 23 小时防溢出）、V9_FERT（假设肥料价格从 $55 跌到 $10 来决定自用）、R51_INPUT（小麦/肥料原料采购）、R53_LABOR（雇工）、CTRTABLE（第 2 步用对手资金 + 小麦库存查表识别已知对手）。
- cha22 已经有手写的"对手识别"和"抢卖"，TTT 正是它们的通用、可学习版本。


## 2. 架构：cha22 骨架 + 可学习插入点
```
obs ─► TTT 对手预测器（快权重，每步用观测到的对手流量更新）──► 对手预测：未来流量、囤货、倾销时刻
  │                                                                │
  ▼                                                                ▼
cha22 骨架：路线动作带 → 反应层 → 补丁 ……  在下列插入点调用学习器：learner_k(状态, cha22 的原决定, 对手预测, 工具特征)
  H1 卖出   H2 肥料   H3 原料采购   H4 雇工   H5 路线   H6 对手识别          （单位动作不动）
```

| # | cha22 里的位置 | 现在怎么决定 | 换成学习后 | 风险 | TTT 的作用 |
|---|---|---|---|---|---|
| H1 | 卖出时机和数量：带子里的卖单 + R36 预留 + RACE/RACEPX/RACEGATE + OVERFLOW | 手写规则，视界固定 40 步，阈值固定 | 每步每种商品由学出来的策略决定卖多少；输入含 cha22 原本打算卖的量（`future_sells`）、对手预测、精确价格/消耗表/持有收益等工具特征 | 低（保留仓容和原料保护） | 核心：预测对手何时倾销 |
| H2 | 肥料自用还是卖（V9_FERT） | 写死的肥料价格假设（$55→$10） | 按预测的真实肥料价格路径决定 | 低到中 | 对手在买还是在卖肥料 |
| H3 | 小麦/肥料的买入时机与数量（R51_INPUT） | 固定的原料需求预测 | 学"什么时候买、买多少" | 中（喂食依赖小麦） | 对手买卖影响价格 |
| H4 | 每天雇几个人（R53_LABOR） | 规则 | 学出来 | 中 | — |
| H5 | 路线选择（第 144、648 步） | 只看前两个商店的决策树 | 输入加上对手画像和我方状态；选的仍是 cha22 自己的完整路线 | 低 | 对手风格影响路线优劣 |
| H6 | 对手识别（CTRTABLE） | 查表，只认识几种已知对手 | 由 TTT 取代，对任何对手持续识别 | 低 | TTT 本身 |
| — | 单位动作（动作带 + 修复层） | 动作带 | 不动 | 高 | — |

- **插桩方式**：不改 cha22 的逻辑，只包装做决策的函数，记录（状态、cha22 的决定、备选），并允许学习器替换决定。
- **安全初始化**：学习器 = cha22 的原决定 + 初始为 0 的修正量，起步时与 cha22 完全一致。
- **保护**：仓容 100、小麦/肥料是原料（cha22 会从仓库取小麦喂食、取肥料施肥），学习器的卖出不能低于原料需求。

## 3. TTT：怎么在正式对局中更新、怎么训练

### 3.1 为什么不放进 cha22 的 front_run
把完美的对手信息喂给它，收益也约等于 0（见 §1.1）。可以顺手把 TTT 的预测接到 `opponent_plan` 上，零成本，但不指望它带来收益。

### 3.2 内环：测试时每步更新
- **输入 x_t**：
  - 市场库存偏差和价格；
  - 当前的城镇商店，由此得到确定的消耗日程；
  - 对手可见的农场：各类动物数量、各种作物的植株数和成熟度、已解锁的地块、资金；
  - 推断出的对手本步流量：u_t = ΔI − 我方流量 + 城镇消耗。成交价为 1 的卖出从库存上看不出来，用对手的资金变化补上；
  - 当前时刻。
- **TTT 层**：k_t = θ_K·φ(x_t)，z_t = k_t + W_t·k_t（TTT-Linear 残差形式）。
- **自监督任务**：用 z 预测对手接下来 h ∈ {1, 4, 24} 步的流量 y^h。这个标签 h 步之后就在对局中揭晓，不需要奖励，也不需要人工标注。
- **更新规则**：

  W_t = (1−λ)·W_{t−1} + λ·W_0 − η ⊙ ∇_W Σ_{已揭晓的样本 s} ‖V·z_s − y_s^h‖²

  - 用最近 4 步做小批量；η 和 λ 是可学习的。
  - W 是 64×64 的矩阵，每步计算量在微秒级。
- **主任务头读取 z_t**，预测三样东西：对手未来 72 步和到终局的流量、对手的隐藏库存、对手的倾销时刻。
  - 这些标签在局内不会揭晓，只在外环中训练。
  - 这正是 TTT 的原理：用局内能揭晓的短期自监督梯度，去改进对长期预测有用的共享表示。

### 3.3 外环：离线训练慢权重
- **数据**：本地共 73,406 局 replay，两个视角合计约 14.7 万条轨迹。用官方解释器精确重放，得到每一步的库存和双方的实际成交流量。
- **训练目标**：
  - 对每个时刻 t，用"当时的" W_t 做预测，此时标签还没揭晓。
  - 损失对所有 horizon 求和，用高斯 NLL 或分位数损失。
  - 梯度反传穿过 720 步的内环，学习 φ、θ_K、V、W_0、η、λ 以及各主任务头。
- **对照组**：去掉内环，即 W_t ≡ W_0 的纯慢模型。两者之差就是 TTT 的价值，对应验证门槛 G2。

### 3.4 "不断更新"发生在三个时间尺度上
1. **局内（每步）**：快权重 W_t 跟着对手的真实行为持续更新，适应这个对手、这一局。
2. **局间（离线）**：用爬虫把我们在天梯上的新对局抓回来，加入外环数据，重新训练慢权重（W_0、η 和编码器），然后重新提交。
   - Kaggle 每局是独立进程，无法跨局保存状态，所以跨局学习只能走"抓 replay → 再训练 → 重新提交"这条路。
3. **版本间**：慢策略的改进由 RL 驱动（见 §4）。

## 4. 训练：先离线 RL，再在线 RL
- **O1 TTT 外环自监督**（§3.3），不需要奖励。
- **O2 插入点上限与分叉数据**：在每个插入点的每次调用处，用 fork 基础设施分出备选（例如卖出：提前、按原计划、推迟、全卖、不卖），各自跑到终局；得到（状态、备选、结果）数据。既用来给插入点排序，也是离线 RL 的数据。
- **O3 特权教师**：市场重放对手（replay 中对手动作开环重放，对我们几乎是精确的对手模拟器）下的完美预见卖出器，只在训练时作为 H1 的老师。
- **O4 离线 RL（IQL/AWR）**：每个插入点一个小策略；奖励 r = 胜负 + 0.25·tanh(资金差/15000)；偏离 cha22 的幅度由优势大小门控（保守改进）。
- **在线 RL：关键步分叉 GRPO**：关键步 = 插入点被调用的时刻；`FarmEnv.clone` 分出 G 个分支，之后都用当前策略继续；A = R − mean(R)（CodeMidas）；MiMo 式 stop-grad ratio、解耦截断，加对离线策略的 KL；对手为会反应的联赛 agent 和自博弈。

## 5. 快慢分离
| 尺度 | 运行什么 | 预算 |
|---|---|---|
| 快（每步） | TTT 更新 → 对手预测 → H1 卖出、H2 肥料；其余由 cha22 骨架给出 | < 20 ms |
| 慢（每天 / 第 144、648 步） | H3 原料采购、H4 雇工（每天）；H5 路线（第 144、648 步）；可选用自带 FarmEnv 做一次分叉模拟 | 单次 ≤ 0.5 s；整局从 60 s 超时储备中最多用 20 s |
| 跨局（离线） | TTT 外环、IQL、GRPO、天梯 replay 回流 | GPU 约 3–5 小时 |

## 6. 为什么不会退化成 cha22
1. cha22 只剩程序骨架和单位动作；各插入点上手调的决策换成学出来的。
2. 每个插入点单独统计：偏离 cha22 的比例、每次偏离的价值（分叉 A/B）；四种高价品的成交均价从基准价的 31–47% 提升到 ≥ 60%。

## 9. 风险与后备
- **所有插入点上限都很小**：说明 cha22 在这些决策上已接近最优，转向在 cha22 自己的动作带上做小幅编辑的离线搜索。
